# OBS 性能真相与管理端“一键上下播”技术方案

| 核心问题 | 结论 |
| :--- | :--- |
| **为什么之前推流非常卡，换浏览器模式效果直线提升？** | **核心根源是“视频重编码参数失控”**。直接推流若使用 CPU 且没有调对预设，CPU 会 100% 满载丢帧；而直播助手内置预设对低配机器做了强制保守限流。 |
| **OBS 对电脑性能到底要求高不高？** | **本体极其轻量（空载仅约 100MB 内存）**。只要关闭画布预览、选对编码器（硬件编码优先或 CPU `ultrafast`），低配挂机宝也能超流畅运行。 |
| **管理端一键上下播与纯上下播脚本** | **通过 OBS 内置的原生 WebSocket (4455 端口)**，管理端网页点击即可开播/停播，bat 脚本仅需一条 `curl` 指令，**全程不杀进程、不重启系统**。 |

## 一、 为什么之前直接推流很卡，浏览器模式效果直线提升？

很多主播都踩过这个坑，表面上看是“软件”问题，**底层本质是“视频编码开销”与“默认参数预设”的差异**：

```text
【模式 A：错误配置的推流模式（卡死）】
输入画面 ──▶ 本地 OBS 采集 ──▶ 开启了本地画面实时预览 (消耗 GPU/CPU)
                                ──▶ 编码器选了默认 x264 (没配 ultrafast，CPU 100%)
                                ──▶ 码率设了 6000+ kbps / 60FPS (挂机宝带宽和算力撑不住)
                                ──▶ 结果：大量丢帧 (Dropped Frames)、画面卡成 PPT

【模式 B：所谓“浏览器模式”为什么流畅？】
1. 很多直播姬在浏览器模式下，强制锁定在 720P 30FPS、码率锁在 2000~2500 kbps；
2. 内部自动启用了极低延迟的硬件加速通道，关闭了多余的重度渲染滤镜；
3. 实际上，只要把 OBS 的编码参数设正确，OBS 的性能与画质上限远高于任何直播姬！
```

## 二、 OBS 在低配挂机宝上的“四大神级神级优化设置”

只要在 OBS 里面做完这 4 项设置，OBS 会比任何直播客户端都要轻快顺滑：

1. **绝对要关闭“画布预览”（省 50% 显卡/CPU 开销）**：
   - 打开 OBS，在中间黑色的直播画面上**右键 ➔ 取消勾选【启用预览】（Disable Preview）**。
   - 挂机宝后台无人值守，根本不需要在本地屏幕上每秒重绘 60 次画面，关掉预览后 GPU/CPU 占用直接减半！
2. **视频编码器设置（针对无独显挂机宝）**：
   - 路径：`设置 ➔ 输出 ➔ 输出模式选择“高级” ➔ 串流`
   - **编码器**：有显卡选 `NVIDIA NVENC H.264`；无显卡选 `x264`。
   - **CPU 使用预设**：必须选 **`ultrafast`**（极速模式，牺牲一点点极限压缩率，换取极低的 CPU 占用）。
   - **码率控制**：`CBR`，码率设为 **`2500 Kbps`**（兼顾高清与低网络负荷）。
3. **视频画布分辨率调优**：
   - 路径：`设置 ➔ 视频`
   - **基础画布 / 输出分辨率**：均设为 `1280x720`（720P 在手机端看画质完全足够，开销仅为 1080P 的 40%）。
   - **常用 FPS**：设为 `30`（不要开 60，挂机宝 30 帧最稳）。
4. **最小化到系统托盘**：
   - 在 OBS 设置中开启“最小化到系统托盘”，挂机宝运行期间把 OBS 缩到右下角托盘，Windows 会自动降低其渲染优先级，省下宝贵资源。

## 三、 管理端（Web后台）与纯上下播脚本架构设计

我们不需要每次粗暴地杀死 OBS 进程。OBS 28+ 原生内置了 **OBS-WebSocket 服务**。管理端可以直接通过网络向 OBS 发送原子指令：

```text
┌─────────────────────────┐
│   主播手机 / 远程浏览器  │
│   http://...:8000/admin │
└────────────┬────────────┘
             │ 点击【一键开播】 / 【一键下播】
             ▼
┌─────────────────────────┐
│   FastAPI Python 管理端 │
│   /api/live/start       │
│   /api/live/stop        │
└────────────┬────────────┘
             │ WebSocket 指令 (端口: 4455)
             │ Request: {"request-type": "StartStream"}
             ▼
┌─────────────────────────┐
│     OBS Studio 进程     │ ──▶ 向 B站 启动/切断推流 (不重启、不杀进程)
│   (常驻挂机宝托盘运行)   │
└─────────────────────────┘
```

### 1. 管理端新增的核心 REST 接口
* `POST /api/live/start`：通知 OBS 启动推流。
* `POST /api/live/stop`：通知 OBS 停止推流。
* `GET /api/live/status`：获取当前推流状态（是否开播中、已播时长、实时推流码率、丢帧率）。

### 2. 纯上下播 BAT 脚本实现
既然有了 REST API，在挂机宝上写“纯上下播”的 bat 就变得极其单纯，只有一行网络请求，绝不杀进程：

* **纯开播脚本：`scripts/start_stream_only.bat`**
  ```bat
  @echo off
  curl -s -X POST http://127.0.0.1:8000/api/live/start
  echo 已向管理端发送 [开始推流] 指令！
  ```

* **纯下播脚本：`scripts/stop_stream_only.bat`**
  ```bat
  @echo off
  curl -s -X POST http://127.0.0.1:8000/api/live/stop
  echo 已向管理端发送 [停止推流] 指令！
  ```
