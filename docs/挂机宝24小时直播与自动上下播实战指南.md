# 挂机宝(Windows) 24小时无人值守直播与 BAT 自动上下播实战指南

| 评估项 | 结论 |
| :--- | :--- |
| **24小时挂机宝开播可行性** | **完全可行，但对挂机宝配置有硬性要求（必须避开纯CPU低配无显卡大坑）** |
| **BAT 脚本自动上下播** | **非常成熟，强烈推荐采用 [OBS Studio + 命令行参数 / WebSocket] 实现** |
| **平台风控等级** | 🟡 **中高风险（需在 B站后台进行 AI 内容合规报备，切忌画面静止纯录播）** |

## 一、 挂机宝 24 小时挂机：4 大致命暗坑与避坑对策

### 暗坑 1：挂机宝“无 GPU / 纯 CPU 虚拟机”导致性能暴死
* **现象**：几十元一个月的廉价挂机宝多为低频 1核/2核、无显卡（或仅有虚拟基础显卡 `Microsoft Basic Display Adapter`）。
* **后果**：
  1. Live2D 模型基于 WebGL 渲染，若无硬件加速，Chromium 只能调用 CPU 模拟软解（SwiftShader），CPU 瞬间拉满 100%；
  2. 视频编码推流若无法调用 NVENC（Nvidia 硬件编解码），仅靠 CPU x264 编码，画面会严重掉帧到 3~5 FPS、声画脱节、甚至进程崩溃。
* **避坑对策**：
  - **硬件选型**：优先选择**带独立显卡（如 GTX 1050/1650/T4 等）或 GPU 算力虚拟化的云主机**；
  - 若预算有限只能选 CPU 机器，必须是 **4核 8G 以上**的高主频机器，且在前端必须关闭粒子特效、Live2D 降低采样率、推流降到 720P 30FPS，视频编码预设调为 `ultrafast`。

### 暗坑 2：远程桌面（RDP）关闭后画面冻结
* **现象**：当你关闭远程桌面（点击右上角 X）退出挂机宝时，Windows 默认会锁定控制台桌面（Lock Console Session），导致图形渲染停止、OBS 浏览器源黑屏或冻结。
* **避坑对策**：
  - 绝对不要直接关 RDP 窗口，必须使用 **`tscon` 转移会话指令**退出，使桌面在后台继续保持激活渲染（详见下文脚本）。

### 暗坑 3：长时间不间断开播的内存泄漏
* **现象**：开播 24~48 小时后，浏览器源的 DOM/WebGL 缓存和 Python 进程可能出现内存缓慢堆积，导致系统内存耗尽。
* **避坑对策**：
  - 建议利用 Windows 任务计划程序，**每隔 12 小时或 24 小时自动下播 2 分钟并重启服务**，自动释放系统资源。

### 暗坑 4：平台巡检风控（一票否决）
* **平台规则**：B站严厉打击“伪装成真人的黑产录播”和“未申报的低质无人挂机”。
* **合规操作**：
  1. 必须在 **B站直播间后台 ➔ 开启“AI 生成合成内容”官方声明**；
  2. 弹幕驱动系统必须保证观众发弹幕能触发真实反馈（有语音、口型或文字变化），绝对不能让画面长时间静止，否则会被判定为挂机录播切断直播推流。

## 二、 自动化上下播技术选型：OBS vs B站直播姬

| 对比项 | OBS Studio（强烈推荐 ⭐⭐⭐⭐⭐） | B站直播姬（一般推荐 ⭐⭐） |
| :--- | :--- | :--- |
| **自动化支持** | 原生支持 CLI 命令行启动参数（`--startstreaming` 等）与 WebSocket API | 闭源 GUI 客户端，无官方命令行参数 |
| **BAT 自动开播** | 一行命令直接启动并推流，100% 成功 | 必须借助 Python/AutoHotkey 模拟点击“开始直播”按钮，容易点偏或弹窗卡死 |
| **资源消耗** | 纯净、极低、可禁用各种无用渲染预览 | 客户端自身包含大量 Webview 广告和附加组件，内存占用偏高 |
| **推流配置** | 输入 B站后台获取的“RTMP 推流地址”与“推流码”即可 | 需扫描登录账号 |

## 三、 开箱即用的自动化脚本套件

在挂机宝的项目根目录下，创建以下自动化脚本：

### 1. 自动开播脚本：`start_live.bat`
此脚本实现：检查并启动 Python 管理端/Docker ➔ 启动 OBS Studio ➔ 自动开始推流。

```bat
@echo off
chcp 65001 >nul
echo ========================================================
echo   [虚拟AI直播系统] 正在启动 24 小时自动开播流程...
echo ========================================================

:: 1. 启动 Docker 容器或本地 Python 管理端
echo [1/3] 正在启动后端中枢服务...
cd /d "D:\__2026Code\priv\B站直播管理"
:: 如果使用 Docker:
docker start ai-live >nul 2>&1 || docker run -d --name ai-live -p 8000:8000 -v "%cd%/configs:/app/configs" -v "%cd%/models:/app/models" virtual-ai-live:v0.2
:: 如果使用原生 Python，取消下一行注释：
:: start /b python -m uvicorn admin.main:app --host 0.0.0.0 --port 8000

:: 等待 5 秒确保后端 HTTP/SSE 服务就绪
timeout /t 5 /nobreak >nul

:: 2. 启动 OBS Studio 并自动开始推流
echo [2/3] 正在启动 OBS Studio 并进入开播推流状态...
set "OBS_DIR=C:\Program Files\obs-studio\bin\64bit"
cd /d "%OBS_DIR%"

:: 参数说明：--startstreaming 启动即推流；--minimize-to-tray 启动最小化到托盘节省 GPU
start "" "obs64.exe" --startstreaming --minimize-to-tray

:: 3. 结果确认
echo [3/3] 开播指令下发完毕！OBS 正在向 B站 推送音画流。
echo ========================================================
```

---

### 2. 自动下播脚本：`stop_live.bat`
此脚本用于定时维护、下播休息或重置状态。

```bat
@echo off
chcp 65001 >nul
echo ========================================================
echo   [虚拟AI直播系统] 正在执行自动下播与资源回收...
echo ========================================================

:: 1. 终止 OBS 进程停止推流 (安全平滑关闭)
echo [1/2] 正在停止 OBS 推流进程...
taskkill /IM obs64.exe /T /F >nul 2>&1

:: 2. (可选) 重启或暂停 Docker 容器以释放累积内存
echo [2/2] 正在清理缓存...
docker restart ai-live >nul 2>&1

echo ========================================================
echo   下播成功！系统已进入待机状态。
echo ========================================================
```

### 3. 【最关键】保持桌面渲染退出 RDP 脚本：`exit_rdp.bat`
在挂机宝桌面上双击这个脚本退出远程桌面，**确保断开连接后图形渲染引擎不被锁死**：

```bat
@echo off
:: 将当前用户会话无锁转接回控制台，保持 WebGL 与 OBS 正常渲染
%windir%\System32\tscon.exe %sessionname% /dest:console
```
> **注意**：每次在挂机宝维护完毕后，**不要点击 RDP 的关闭按钮（X），而是右键“以管理员身份运行” `exit_rdp.bat`**。

---

### 4. 崩溃自愈守护守护脚本：`watchdog.bat`
防止 OBS 或后台服务意外崩溃导致黑屏，守护进程每隔 60 秒检查一次状态，崩溃则自动拉起：

```bat
@echo off
chcp 65001 >nul
echo 正在运行 7x24 小时直播守护监控...

:loop
:: 检查 OBS 进程是否存在
tasklist | findstr /i "obs64.exe" >nul
if errorlevel 1 (
    echo [%date% %time%] 警告: 检测到 OBS 掉线，正在自动拉起开播...
    call "D:\__2026Code\priv\B站直播管理\start_live.bat"
)

:: 每隔 60 秒检测一次
timeout /t 60 /nobreak >nul
goto loop
```

## 四、 配合 Windows 任务计划程序实现 7x24 自动化轮换

为了防止长时间开播引起的任何偶发卡顿，推荐在 Windows 计划任务中配置日常轮换：

1. **每天凌晨 04:00 自动执行 `stop_live.bat`**（下播释放一天累积的内存与缓存）。
2. **每天凌晨 04:05 自动执行 `start_live.bat`**（重新自动启动开播，全程无缝衔接）。
3. 主播只需在手机端 B站 App 收到开播通知即可，真正实现“零人工值守”。
